Agile Retrospective

Sprint 1 Retrospective

What Went Well

- Project requirements and objectives were discussed and clearly understood.
- The basic project workflow was planned.
- The technology stack and development approach were identified.
- Initial project documentation and backlog were prepared.
- Team members discussed the responsibilities and tasks for the sprint.

What Could Be Improved

- Some requirements were not completely clear at the beginning.
- More time was needed to understand the project workflow.
- Task estimation could have been more accurate.
- Documentation needed to be updated more regularly.

Action Items

- Finalize requirements before starting implementation.
- Break large tasks into smaller tasks.
- Update the backlog and progress documentation regularly.
- Discuss technical issues during daily stand-up meetings.

---

Sprint 2 Retrospective

What Went Well

- Core development activities progressed according to the sprint plan.
- Face monitoring and examination monitoring functionality was developed.
- Database-related work was integrated with the application.
- Testing was started alongside development.
- Team communication and task tracking improved.

What Could Be Improved

- Some implementation issues required additional debugging.
- Integration between different modules took more time than expected.
- More test cases were required for unusual or unexpected situations.
- Some documentation was updated after development instead of during development.

Action Items

- Perform integration testing earlier.
- Maintain test cases while implementing each feature.
- Document important technical changes immediately.
- Allocate additional time for debugging and integration.

Sprint 3 Retrospective

What Went Well

- Major project features were integrated successfully.
- Proctoring events and monitoring activities were tested.
- Evidence and reporting functionality was improved.
- Testing helped identify and fix several issues.
- Project documentation was updated based on the completed work.

What Could Be Improved

- More comprehensive testing is required for different examination scenarios.
- Some edge cases may still require additional validation.
- Final documentation can be made more detailed and consistent.
- The overall system can be optimized further for reliability and performance.

Action Items

- Complete final system testing.
- Verify database records and evidence paths.
- Test multiple suspicious events without overwriting evidence.
- Review and finalize all Agile documentation.
- Prepare the final project demonstration and report.

---

Overall Retrospective

What Went Well

- The project followed an iterative Agile development approach.
- Requirements were converted into backlog items and sprint tasks.
- Regular progress tracking helped monitor development.
- Testing was performed during the development process.
- Feedback and issues were used to improve subsequent sprint activities.

What Could Be Improved

- Initial task estimation could be more accurate.
- Documentation should be maintained continuously.
- Integration and testing should begin earlier.
- More time should be allocated for debugging and edge-case testing.

Lessons Learned

- Breaking a large project into smaller sprint tasks makes development easier to manage.
- Regular progress reviews help identify problems early.
- Testing during development reduces issues during final integration.
- Clear documentation makes the project easier to understand and maintain.

Future Improvements

- Improve face detection accuracy.
- Improve suspicious-event detection.
- Add more comprehensive automated testing.
- Improve the integrity report and evidence presentation.
- Optimize system performance and reliability.
